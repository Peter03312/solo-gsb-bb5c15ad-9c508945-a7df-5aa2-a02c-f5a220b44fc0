# 矩形纸张裁切排样 Web 应用

面向小型印刷作坊的矩形纸张裁切（排样）工具。给定**母纸尺寸、刀缝宽度、
张数上限、搜索状态数上限**、各类**成品的长宽、份数、能否旋转**，以及
按物理纸号登记的**母纸瑕疵区清单（可选）**，自动给出：

- **逐张实际使用母纸（标注物理纸号）的排样图**（SVG，成品上色、刀缝红色、
  瑕疵区紫色斜纹、旋转件标 ↻）；
- **按执行顺序排列的贯通式裁切步骤**（每刀贯穿当前余料，注明刀向、刀口
  位置、刀长及刀后两块余料尺寸）；
- 每类成品的**需求份数 / 实际成品数**；
- 可**导出/打印裁切单**（自包含 HTML，标明所依据的输入版本、每张用纸的
  物理纸号与该纸瑕疵区坐标）。

后端为 **Python 3 + SQLite**，前端为原生 HTML/CSS/JS。
**仅使用 Python 标准库，零第三方依赖。**

---

## 一、快速启动（Docker Compose 一键启动）

前置：已安装 Docker 与 Docker Compose（`docker compose version` 可用）。

```bash
docker compose up -d --build
```

启动后访问：

- **地址：** <http://localhost:8000>
- **端口：** 容器内固定 `8000`，宿主机默认映射 `8000`。

如需改用宿主机其他端口：

```bash
PORT=9000 docker compose up -d --build
# 访问 http://localhost:9000
```

停止与查看日志：

```bash
docker compose down          # 停止（数据保留在卷 cutting-data 中）
docker compose logs -f       # 跟踪日志
```

首次启动会自动初始化 SQLite 数据库（建表并写入一份可直接试算的示例输入），
无需手工执行任何初始化命令。

### 不用 Compose（仅 Docker）

```bash
docker build -t cutting-planner .
docker run -d --name cutting-planner -p 8000:8000 \
  -v cutting-data:/data cutting-planner
```

## 三、配置（环境变量）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `HOST` | `0.0.0.0` | 监听地址 |
| `PORT` | `8000` | 容器/服务监听端口 |
| `DB_PATH` | `/data/cutting.db`（容器）或绝对路径 | SQLite 数据库文件路径，所在目录会自动创建 |

Compose 中通过 `PORT`（宿主机侧）调整映射端口；数据库保存在具名卷
`cutting-data`（挂载到容器 `/data`）中，容器重建后数据仍在。

### 输入取值约束（服务端强校验，非法输入不落库）

- 母纸长、宽；成品长、宽：**正整数毫米**（1–10000）；
- 刀缝宽度：**非负整数毫米**（0–1000，且必须小于母纸长宽）；
- 成品份数、张数上限、搜索状态数上限：**正整数**；
- 成品名称非空、不重复；成品最多 12 种。
- **母纸瑕疵登记（可选，字段 `defects`）**：数组，每项
  `{"sheet_no": 纸号, "regions": [...]}`；
  - 纸号为 **1..张数上限** 的正整数，**同一纸号至多登记一次**
    （重复登记整张拒绝、不落库）；未登记的纸号视为完好；
  - `regions` 为**非空**矩形清单，每区给出左上角坐标 `x,y`
    （非负整数）与宽高 `w,h`（正整数），单位毫米，且必须完全位于母纸内
    （`x+w ≤ 母纸长`、`y+h ≤ 母纸宽`）；
  - **同一张纸的瑕疵区允许相互重叠**；单纸瑕疵区数量上限 200；
  - 任何尺寸非正、坐标为负、越界或纸号重复/超界的登记都会返回 400 与
    字段级错误，**不会写入数据库**。

任何非法输入（含小数、负数、0、非数字）都会被拒绝并返回 400 与字段级
错误提示，**不会写入数据库**。

## 四、使用流程与关键规则

1. 在页面填写母纸/刀缝/张数上限/搜索状态数上限和成品清单，点击
   **“保存输入并搜索”**。
2. 每次保存输入都会生成一个**单调递增的输入版本号 vN**，并使任何旧方案
   **立即失效**。
3. 搜索结果有三种，界面与 API 明确区分：
   - **找到可行方案（found）**：满足全部份数的排样（找到即可，不追求最优）。
     检查无误后点 **“保存此方案”**，随后可 **“导出裁切单”**。
   - **已穷尽，确认无解（infeasible）**：在当前输入与旋转限制下已穷尽搜索，
     不存在可行贯通刀切法（含面积必然超限等确定性预检）。
   - **搜索预算耗尽（budget_exhausted）**：在给定状态数内**未穷尽**搜索，
     **不能据此声称无解**；可**增大“搜索状态数上限”后重试**。
4. **导出裁切单**会标明所依据的输入版本；仅当方案有效（已保存且版本与
   当前输入一致）时才允许导出，否则返回 409 并拒绝导出。
5. “仅按当前输入试算”不会保存输入，只用于探索；试算方案需先“保存此方案”
   才能导出裁切单。

### 裁切模型（满足题目约束）

- 每一刀都是沿直线**贯穿当前矩形余料**的贯通刀（guillotine cut），一刀
  把该余料分成两块；
- 切分时**扣除刀缝宽度**（两块余料之间留出等宽刀缝，刀缝不是成品）；
- 成品**不得重叠、不得越界**；成品叶子与其所在末端余料尺寸完全相等；
- 严格遵守**旋转限制**（不允许旋转的成品只能按原长宽摆放）；
- **母纸可带局部矩形瑕疵区**：求解时可以**选择或跳过任意具体物理纸号**
  （编号 1..张数上限，跳过的纸不出现在方案里）；**成品矩形不得与该纸
  任一瑕疵区有面积重叠**（边相切允许），而**刀路（含刀缝）与废料允许
  穿过瑕疵区**——即只避让成品，不要求避让切口；
- 搜索刀口位置按“成品边长 / 镜像边长”归一化枚举；带瑕疵的余料额外
  纳入“瑕疵边缘 / 镜像”候选，依据 guillotine normal-patterns 定理在
  带瑕疵情形下的扩展保证：**若存在可行贯通刀排样，就不会因位置归一化
  而漏掉**（在状态预算内）。仓库 `test_defects.py` 以全枚举整数刀口的
  独立朴素判定器做随机交叉验证。

服务端在**保存与导出**前还会对方案做一次独立于求解器的几何核验
（越界、重叠、旋转、刀缝侵入、刀路贯通与区域自洽、实际数量=需求），
并额外核验**物理纸号合法且不重复、回显瑕疵清单与登记逐区一致、每个
成品不压该纸瑕疵**，任何被篡改或不自洽的方案都会被拒绝。

## 五、HTTP API（供脚本/集成调用）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/state` | 当前输入（含版本、瑕疵登记）+ 方案状态（有效则内含方案） |
| POST | `/api/inputs` | 校验并替换输入（含 `defects` 瑕疵登记）；成功后版本 +1、旧方案失效；非法 400 |
| POST | `/api/solve` | 按当前版本输入试算，body 可覆盖 `state_limit`；返回 `found/infeasible/budget_exhausted` |
| POST | `/api/solution` | 保存试算方案（服务端几何核验 + 瑕疵避让核验 + 版本核对） |
| DELETE | `/api/solution` | 废弃当前方案 |
| GET | `/api/cutting-sheet` | 导出有效方案裁切单 HTML（含各纸纸号与瑕疵区）；失效/无方案返回 409 |

`POST /api/inputs` 请求示例（瑕疵登记可选；省略 `defects` 或给 `[]`
表示全部母纸完好）：

```json
{
  "sheet_w": 450, "sheet_h": 320, "kerf": 3,
  "max_sheets": 6, "state_limit": 200000,
  "products": [
    {"name": "卡片A", "length": 120, "width": 80, "qty": 8, "rotatable": true},
    {"name": "卡片B", "length": 200, "width": 60, "qty": 4, "rotatable": false}
  ],
  "defects": [
    {"sheet_no": 1, "regions": [
      {"x": 10, "y": 12, "w": 120, "h": 80},
      {"x": 300, "y": 200, "w": 90, "h": 70}
    ]},
    {"sheet_no": 3, "regions": [
      {"x": 0, "y": 0, "w": 200, "h": 40}
    ]}
  ]
}
```

瑕疵坐标为该纸母纸内绝对坐标，原点左上角，x 向右、y 向下，单位毫米；
同纸瑕疵区可重叠；纸号 2/4/5/6 未登记即视为完好。

`POST /api/solve` 请求示例：

```json
{ "input_version": 3, "state_limit": 1000000 }
```

返回（节选）：

```json
{ "input_version": 3,
  "result": { "status": "found", "sheets_used": 2,
              "states_used": 134053,
              "sheets": [ { "sheet_index": 1, "sheet_no": 2,
                            "defects": [], "leaves": [ ... ],
                            "gaps": [ ... ], "cuts": [ ... ] },
                          { "sheet_index": 2, "sheet_no": 4,
                            "defects": [ {"x":0,"y":0,"w":200,"h":40} ],
                            "leaves": [ ... ], "cuts": [ ... ] } ],
              "counts": [ ... ] } }
```

说明：

- `sheet_index` 为实际用纸的顺序序号（第几张用纸），`sheet_no` 为
  **物理母纸纸号**；求解器可以跳过带瑕疵或不想使用的纸号，故二者不必
  相同，未出现的纸号即未使用；
- 每页 `defects` 回显该纸**登记的瑕疵区**（完好纸为 `[]`），保存与
  导出时服务端会核对其与输入逐区一致，并检查每个 `leaves` 成品矩形
  不与这些瑕疵区面积重叠（刀缝 `gaps` 与废料不受此限）。

一段不依赖第三方库的命令行调用示例：

```bash
# 1) 保存输入（含瑕疵登记）
curl -sS -X POST http://localhost:8000/api/inputs \
  -H 'Content-Type: application/json' -d '{
    "sheet_w":200,"sheet_h":150,"kerf":3,"max_sheets":3,"state_limit":500000,
    "products":[{"name":"名片","length":90,"width":54,"qty":6,"rotatable":true}],
    "defects":[{"sheet_no":1,"regions":[{"x":0,"y":0,"w":60,"h":40}]}]
  }'
# 2) 试算（用返回中的 input_version）/ 3) 保存 / 4) 导出
curl -sS -X POST http://localhost:8000/api/solve \
  -H 'Content-Type: application/json' -d '{"input_version":1}'
```

`status` 为 `infeasible` 表示已穷尽确认无解（含所有纸号选择与瑕疵避让
均不可能的情形）；为 `budget_exhausted` 表示预算耗尽、**不是**无解，
请加大 `state_limit` 重试。

### 浏览器界面本轮用法

- “母纸瑕疵登记”区点 **+ 登记一张带瑕疵母纸**，填纸号与该纸若干
  瑕疵区（左上角 x/y、宽/高，mm）；同一纸号只需登记一次，保存输入时
  服务端会拒绝重复纸号、非正尺寸与越界区且不落库；
- 排样结果中每张用纸标题与 SVG 左上角都标出**物理纸号**，瑕疵区以
  **紫色斜纹虚线块**绘制，页面顶部列出“实际使用纸号”；
- 裁切单每页给出纸号、本纸瑕疵区坐标区间（含/不含登记瑕疵均明示），
  并在图例中说明成品避让、刀路可穿过瑕疵。

## 六、项目结构

```
.
├── Dockerfile                 # 零第三方依赖的镜像
├── docker-compose.yml         # 一键启动（含数据卷与健康检查）
├── requirements.txt           # 说明文件（无需安装第三方包）
├── README.md
└── app/
    ├── server.py              # 标准库线程 HTTP 服务器入口（读环境变量、初始化DB）
    ├── app.py                 # WSGI 路由 / API
    ├── validation.py          # 输入强校验（非法不落库）
    ├── solver.py              # 贯通刀排样求解器（精确目标填充 + 状态预算）
    ├── verify.py              # 服务端独立方案几何核验
    ├── cutting_sheet.py       # 裁切单 HTML/SVG 导出
    ├── database.py            # SQLite 持久化（输入版本 + 方案失效）
    └── static/                # 浏览器界面
        ├── index.html
        ├── style.css
        └── app.js
```
